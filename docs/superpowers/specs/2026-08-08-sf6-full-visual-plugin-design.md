# SF6 Full Visual Music Trigger 设计规格

## 1. 产品目标

构建一个仅面向 Windows PC 版《街头霸王 6》的开源本地音乐触发器。程序通过捕获游戏窗口已经显示的像素，识别 P1/P2 的 SA3/CA 满气与实际耗气；确认发动后立即播放用户配置的主音乐，并在本地判断命中、格挡、打空、重置或不确定结果。

产品必须支持现代与经典操作方式，不要求读取或配置按键。核心功能离线运行，不上传画面，不读取游戏内存，不注入游戏进程，不修改游戏文件，不模拟输入，不访问对局网络数据。

## 2. 支持范围

首个正式支持范围：

- Windows 10 22H2 与 Windows 11 23H2 及以上。
- Steam PC 版《街头霸王 6》。
- 排位、休闲、自定义房间、训练模式与本地对战。
- P1、P2 与本地双人独立音轨。
- 现代、经典与动态操作模式；操作方式不参与核心触发判定。
- 无边框窗口与普通窗口模式；独占全屏仅在捕获后端能够稳定取得帧时支持。
- 16:9 的 1920×1080、2560×1440、3840×2160 为首批验收分辨率；其他比例通过校准档案进入实验支持。
- 用户自选的命中音乐、格挡音乐、打空音乐，以及每类独立音量和淡入淡出时间。

不承诺支持主机原生运行、采集卡输入、云游戏、游戏内存读取、Mod、脚本操作或任何影响对局的自动化。

## 3. 安全与在线边界

程序是外部屏幕伴侣，不是游戏 Mod。所有战斗状态都必须来自用户屏幕上已可见的像素。任何模块都不得：

- 打开或读取 `StreetFighter6.exe` 的进程内存；
- 注入 DLL、安装驱动、Hook 游戏函数或修改游戏资源；
- 发送键盘、鼠标或手柄输入；
- 代理、分析或修改网络流量；
- 在未经明确同意时保存或上传截图、录像、玩家姓名或 Fighter ID；
- 宣称得到 Capcom 官方授权，或保证不会触发未来规则变化带来的风险。

默认诊断只保存数值与匿名事件 ID。保存裁剪画面必须由用户主动开启，并在面板显示明确状态。项目不提供隐藏玩家姓名之外的隐私保证。

## 4. 总体架构

```text
SF6 窗口捕获
  -> HUD 校准与布局档案
  -> GaugeTracker(P1/P2)
  -> ConfirmedSuperEvent
  -> AudioDirector 立即播放主音乐
  -> OutcomeObserver 收集 2~6 秒多区域时序
  -> RuleClassifier + 可选 LocalModelClassifier
  -> HIT / BLOCK / WHIFF / RESET / UNKNOWN
  -> AudioDirector 保持、替换、淡出或保守不变
```

核心触发器与结果分类器必须解耦。结果分类器失效、模型缺失或置信度不足，不得撤销已经确认的耗气事件，也不得制造新的大招事件。

## 5. 组件边界

### 5.1 WindowCapture

只负责定位 SF6 客户区并输出类型化捕获样本。首选 DXGI 桌面复制，失败时可回退 Windows Graphics Capture 后端。窗口移动、缩放、最小化、窗口隐藏或 DWM cloaked、黑帧、无新帧、捕获错误和不支持的显示输出必须成为显式状态，不得复用陈旧帧冒充新帧。`OCCLUDED` 只表示窗口不可见或被 DWM 标记为 cloaked；本组件不承诺检测窗口仍可见但被其他窗口覆盖的情况。

输出接口：

```python
CapturedFrame(frame_id: int, image: np.ndarray, monotonic_time: Real, geometry: ClientGeometry)
CaptureStatus = RUNNING | OCCLUDED | MINIMIZED | LOST | STOPPED
CaptureIssue = BLACK_FRAME | NO_NEW_FRAME | WINDOW_CHANGED | GEOMETRY_CHANGED | BACKEND_ERROR | UNSUPPORTED_OUTPUT
CaptureSample(status: CaptureStatus, frame: CapturedFrame | None, issue: CaptureIssue | None)
```

`RUNNING` 当且仅当样本携带合法、调用方自有且可写的 `uint8 H×W×3` BGR 帧；`LOST` 必须携带明确 `CaptureIssue`，其余状态不得携带帧或问题。窗口身份使用 `(hwnd, pid, process_created_at_ticks)`，窗口查询本身连续两次核对身份、客户区几何与显示器。每次阻塞捕获前后还必须分别取得稳定窗口与唯一输出快照；任何返回目标或变化异常中的所有可用身份都先与当前已附着身份比较，任一外来身份均按窗口身份变化锁定，只有全部身份一致时才允许按几何变化重建。阻塞期间发生的身份、几何、显示器或输出变化会丢弃刚取得的像素，绝不先提交帧 ID 或时间水位。Win32 客户区查询在 per-monitor-V2 线程 DPI 上下文中执行并在 `finally` 恢复；客户区两个角分别转换到桌面坐标，再转换为唯一 DXcam 输出内的相对坐标。跨屏、输出不唯一、窗口身份变化或几何变化均保守拒绝旧帧。

DXcam 仅在用户按“开始”后懒加载；Phase 1 将适配边界锁定在 `dxcam[winrt] 0.3.x`，通过专用版本适配层把结构化输出描述转换为稳定的内部类型，不解析人类可读字符串。适配器使用 `video_mode=False`，并通过原子 `get_latest_frame(copy=True, with_timestamp=True)` 同时取得自有像素与后端时间戳。相同像素只要后端时间严格推进仍是新帧；重复或倒退时间不是新帧；只有精确全零数组属于黑帧，近黑、全白和低对比度帧继续交给下游 HUD 可见性判定。

### 5.2 HudProfile 与校准

首次运行向导从实时画面确认 P1/P2 超级槽区域、战斗画面区域和可选训练 HUD 区域。坐标以客户区归一化比例保存，并记录分辨率、宽高比、HUD 缩放、语言、亮度/HDR 标记与游戏版本备注。

开源仓库不分发从游戏截图裁剪出的模板。模板由用户本地校准产生；若后续发布官方允许的通用特征包，必须独立列出来源与许可证。

### 5.3 GaugeTracker

每侧独立状态机：

```text
DISARMED -> ARMED -> SPEND_CANDIDATE -> CONFIRMED -> COOLDOWN -> DISARMED
```

- `ARMED`：满 3 格或 CA 标记在连续至少 5 个采样中稳定出现。
- `SPEND_CANDIDATE`：满气字形、槽填充或局部结构出现显著变化。
- `CONFIRMED`：最近 5 个有效样本中至少 3 个确认气槽从 3/CA 变为 0，并且变化持续不少于 100ms；从满槽释放 SA1 或 SA2 后剩余 2/1 格不得确认。
- `COOLDOWN`：一次确认后锁定该侧，直到新气槽状态稳定或进入新回合，防止联网回滚与过场反复生成同一事件。
- 双方 HUD 同时消失、回合重置、菜单切换或捕获丢失时，不得确认耗气。

现代输入只允许作为可选的低延迟提示，绝不能成为触发前置条件，也不能单独播放音频。

### 5.4 ConfirmedSuperEvent

```python
ConfirmedSuperEvent(
    event_id: str,
    side: Literal["P1", "P2"],
    confirmed_at: float,
    pre_spend_frame_id: int,
    confirmed_frame_id: int,
    profile_id: str,
)
```

事件一经产生，AudioDirector 在同一处理周期执行 `stop -> play(main)`。P1/P2 使用独立调度器与声道。

### 5.5 OutcomeObserver

只在 ConfirmedSuperEvent 后启动，按 10~15 FPS 保存内存环形缓冲中的低分辨率多区域特征，不默认写入磁盘：

- 中央战斗区域时序；
- 对手血条的事件内变化；
- 可见的伤害、连击、格挡或重置区域；
- HUD 可见性、黑帧和捕获新鲜度；
- 从耗气前 1 秒到耗气后最多 6 秒的时间关系。

静态非零伤害、单帧血条变化、整屏平均差和“重新开始格斗”提示都不能单独证明命中。

### 5.6 结果分类

统一输出：

```python
OutcomeDecision(
    label: Literal["HIT", "BLOCK", "WHIFF", "RESET", "UNKNOWN"],
    confidence: float,
    decided_at: float,
    evidence: tuple[str, ...],
)
```

规则分类器始终存在，负责明显事件与安全兜底。可选本地模型仅分析 ConfirmedSuperEvent 之后的低分辨率多区域短序列，输出相同接口。两者通过可配置融合器合并：

- 高置信度 `HIT`：保持主音乐；
- 高置信度 `BLOCK`：按用户设置保持主音乐或切换格挡音频；
- 高置信度 `WHIFF`：淡出主音乐并播放打空音频；
- `RESET`：停止待判事件，不把重置当命中；
- `UNKNOWN` 或冲突：默认保持主音乐并记录诊断，不强行切换。

模型不得绕过 GaugeTracker，也不得通过画面动作自行创建事件。

### 5.7 本地模型

模型以可选 ONNX 模型包加载，默认 CPU 推理，缺失时程序完整运行规则模式。模型包包含：

- 模型权重；
- 输入区域与采样规范；
- 标签映射；
- 模型版本、适配游戏版本和许可证；
- SHA-256 校验值；
- 在独立用户/会话留出集上的混淆矩阵与各类召回率。

模型不得包含云端调用或后台上传。低于配置置信度时必须输出 `UNKNOWN`。

### 5.8 AudioDirector

每侧使用独立声道，预览使用第三个专用声道。音频策略：

- 确认耗气：立即停止该侧旧音轨并播放主音乐；
- 命中：不重播；
- 格挡：按配置保持主音乐或淡出后播放格挡音频；
- 打空：按配置淡出后播放打空音频；
- 重置：停止待播替换，不把重置映射为任何结果音频；
- 不确定：默认保持当前主音乐。

所有音量强制限制在 0~100%，面板显示实际百分比。

## 6. 用户界面

常驻面板包含：

- SF6 捕获状态与客户区分辨率；
- P1/P2 启用开关；
- 每侧角色备注与主音乐、格挡音乐、打空音乐；
- 独立音量、淡入淡出与试听；
- 开始、停止、退出；
- 校准 HUD、验证当前档案；
- 规则模式/本地模型模式与模型状态；
- 当前事件状态、结果、置信度与简短证据；
- 诊断保存开关和隐私提示。

程序启动不自动查找游戏；用户按“开始”后才连接捕获。停止和退出必须协作式结束线程、释放捕获与声道，不依赖 Ctrl+C。

## 7. 数据集与标注

当前旧项目的诊断标签来自旧算法，不能当作模型真值。新版提供本地事件回放与标注工具，用户可将事件标为 HIT/BLOCK/WHIFF/RESET/UNKNOWN。

训练片段采用事件级多区域裁剪，默认不包含玩家姓名区。训练/验证/测试必须按用户、录制会话和环境分组，禁止把同一录像的相邻帧随机拆入不同集合。

社区贡献必须为主动导出；仓库不接收未授权音乐、整段比赛录像或带个人路径的配置。数据集、模型权重和源代码分别声明许可证。

## 8. 开源仓库与发布

新仓库不得复制旧项目中的 `music/`、`diagnostic_captures/`、`logs/`、`screenshots/`、个人 `app_config.json`、`input_config.json` 或本机绝对路径。必须包含：

- MIT 源代码许可证；模型权重必须使用独立许可证与来源说明，训练数据在版权和贡献授权未完成审查前不随仓库分发；
- `.gitignore`、依赖许可证清单和隐私说明；
- 示例配置只使用相对路径和虚构素材名；
- 用户自行选择音乐的说明，不捆绑商业歌曲；
- “非 Capcom 官方产品”声明；
- 可复现测试和打包脚本。

Windows 发布包使用普通用户权限，不能要求管理员、驱动、服务或内核组件。首次运行不联网；可选更新检查必须明确开关。

## 9. 性能目标

- 1080p/60 游戏时，插件平均 CPU 占用目标不超过一个现代 6 核桌面 CPU 的 8%。
- 无模型模式内存目标不超过 300MB；加载本地模型后目标不超过 600MB。
- 从 HUD 首次可见耗气到主音乐播放的中位延迟不超过 250ms，P95 不超过 400ms。
- 捕获处理不得阻塞音频调度和 UI 主线程。
- 捕获不足、帧陈旧或模型超时时优先输出 UNKNOWN，不得猜测。

## 10. 测试与验收

测试分四层：

1. 纯单元测试：坐标换算、状态机、结果融合、音频调度、配置与隐私默认值。
2. 录制帧回放：满气不耗气、满槽释放 SA1/SA2 后剩余 2/1 格、真实 SA3/CA 清零、回合重置、黑帧、窗口缩放、P1/P2 与连续事件。
3. 数据集基准：按独立环境评估 HIT/BLOCK/WHIFF/RESET/UNKNOWN，报告混淆矩阵；不以旧算法标签作为真值。
4. SF6 实机验收：现代/经典、P1/P2、命中/格挡/打空、排位等价画面、连续释放、窗口变化和停止/退出。

实机验收只能在 Computer Use 能访问宿主 SF6 窗口后进行；MK1 与 SF6 不得同时启动。没有实机证据时只能称为离线候选版。

## 11. 分阶段交付

### 阶段 A：开源安全基础

建立干净仓库、许可证、配置、捕获接口、HUD 档案、事件模型、测试框架和无版权素材约束。

### 阶段 B：纯画面耗气触发

实现 GaugeTracker、P1/P2、音频调度、持久面板与录制帧回放。此阶段必须已经兼容现代/经典并稳定触发主音乐。

### 阶段 C：结果观察与规则分类

实现多区域时序、HIT/BLOCK/WHIFF/RESET/UNKNOWN、保守音频策略和本地标注工具。

### 阶段 D：可选本地模型

在获得人工真值数据后训练、评估并发布独立 ONNX 模型包。模型未达到独立环境验收门槛时，不得默认启用。

### 阶段 E：在线场景发布验收

完成跨分辨率、P1/P2、现代/经典和实际在线场景的手工验收，生成版本化证据并打包 Windows 发布版。

## 12. 完成定义

“完整版”只有同时满足以下条件才能标记稳定发布：

- 控制方式无关的 P1/P2 真实耗气触发通过自动回放和实机测试；
- 命中、格挡、打空、重置、不确定均有人工真值验收；
- 低置信度不会错误切换打空音频；
- 在线运行不读取、修改或控制游戏；
- 用户可完全关闭诊断和模型；
- 开源仓库不含商业音乐、个人数据或未经许可的游戏素材；
- Windows 安装包、源码构建、许可证和隐私文档完整；
- SF6 实机验收完成且游戏在测试结束后关闭。
